# Анализ тональности русских твитов: TF-IDF + MLP

Учебный проект по бинарной классификации сообщений из [RuTweetCorp](https://www.kaggle.com/datasets/maximsuvorov/rutweetcorp). Ноутбук загружает и очищает данные, строит TF-IDF-признаки, обучает многослойный перцептрон (MLP), оценивает его на отложенной выборке и разбирает ошибки и веса модели.

**Основной результат:** Accuracy **0,8036** на **42 231** тестовом сообщении. Основная модель использует 32 скрытых нейрона и текст без лемматизации, но со скобочными смайлами. F1: **0,7975** для негатива и **0,8093** для позитива. Эти числа сохранены в выводе ноутбука; при повторном запуске возможны небольшие различия из-за версий библиотек и платформы.

## Быстрый запуск для преподавателя

Понадобятся **Git**, **Docker Desktop** с запущенным Docker Engine и два CSV-файла из RuTweetCorp. Команды выполняются в терминале в корне проекта.

1. Склонируйте репозиторий и перейдите на ветку с домашним заданием:

   ```bash
   git clone https://github.com/avtorpc/fundament_nlp.git
   cd fundament_nlp
   git switch student
   ```

2. Скачайте [RuTweetCorp на Kaggle](https://www.kaggle.com/datasets/maximsuvorov/rutweetcorp) и положите исходные CSV сюда:

   ```text
   fundament_nlp/
   ├── data/
   │   ├── negative.csv
   │   └── positive.csv
   └── Untitled.ipynb
   ```

   Создайте `data/`, если каталога нет. В обоих CSV должны быть столбцы `ttext` (сообщение) и `ttype` (исходная метка `-1` или `1`). Данные не включены в Git; доступ к Kaggle и скачивание выполняются отдельно.

3. Соберите и запустите один сервис `notebook`:

   ```bash
   docker compose up --build -d
   docker compose ps
   ```

   Сборка впервые загрузит базовый образ Python и установит зависимости. Флаг `-d` оставляет контейнер работать в фоне. В `docker compose ps` сервис `notebook` должен иметь состояние `running`.

4. Получите **свой локальный** токен Jupyter:

   ```bash
   docker compose logs notebook
   ```

   В выводе найдите адрес вида `http://127.0.0.1:8888/lab?token=...` и откройте его на **том же компьютере**, где работает Docker. Если старый адрес не подходит, вновь посмотрите текущие логи: при новом запуске токен может измениться. Токен нужен только для локального входа в Jupyter; преподавателю не требуется токен автора проекта. Адрес `127.0.0.1` не открывает доступ к чужому компьютеру. Порт опубликован только на локальном интерфейсе.

5. В JupyterLab откройте `Untitled.ipynb`. Сохранённые выводы и итоговый текст можно просмотреть **без запуска ячеек**. Для проверки работы с нуля выберите в верхнем меню **Run → Restart Kernel and Run All Cells**. Выполняйте ноутбук сверху вниз; повторное обучение и лемматизация могут занять несколько минут. Последняя пустая ячейка ничего не делает.

6. Остановите контейнер после проверки:

   ```bash
   docker compose down
   ```

Файлы, которые Jupyter сохраняет в `/workspace`, появляются в каталоге проекта на компьютере благодаря подключению `.:/workspace`. Данные из `data/` доступны контейнеру по пути `/workspace/data/`. Если изменился `requirements.txt` или `Dockerfile`, повторите `docker compose up --build -d`.

## Где искать результаты в ноутбуке

Названия **ШАГ 01–21** в ячейках обозначают порядок работы. Числа в квадратных скобках слева от ячеек Jupyter обозначают порядок **последнего выполнения**, а не номер шага.

| Шаги | Что показано |
| --- | --- |
| 01–09 | Импорт, чтение CSV, перевод меток `-1 → 0`, проверка дублей, очистка текста, удаление непригодных сообщений и разделение на обучение/тест. |
| 10–11 | TF-IDF-словарь и небольшой фрагмент числовой матрицы. Словарь и IDF строятся только по обучающим текстам. |
| 12–13 | Обучение основной MLP с 32 скрытыми нейронами; Accuracy, Precision, Recall, F1 по обоим классам и график матрицы ошибок на тесте. |
| 14–15 | Примеры неверных ответов, включая случаи рядом с порогом и уверенные ошибки. |
| 16–18 | Отдельный опыт с лемматизацией на том же разделении данных. Accuracy **0,7998** против **0,8036** у основной модели. |
| 19 | Топ-20 слов для позитива и негатива, рассчитанный по весам основной MLP; отдельно показано влияние скобочных смайлов. |
| 20 | Семь собственных фраз: авторские метки, ответы модели и вероятности обоих классов. Совпадений с авторской оценкой — **5 из 7**. |
| 21 | Итоговый вывод о качестве, ограничениях TF-IDF + MLP и сравнении с контекстными моделями. |

В тестовой матрице ошибок: **4 427** негативных сообщений названы позитивными (FP), **3 868** позитивных названы негативными (FN). Ручные семь фраз служат иллюстрацией поведения модели и не заменяют оценку на 42 231 тестовом сообщении.
